# Л3 — Рішення з ціною помилки

Класифікатор каже, наскільки ймовірна подія. Рішення з цього виходить лише тоді, коли відомо, скільки коштує кожна помилка: зайвий виїзд чи пропущена відмова.

Обленерго обслуговує парк розподільчого обладнання. Диспетчер планує об'їзд на наступний тиждень. Ваша задача — навчити класифікатори на історії відмов, перевірити дані на пастки й вирішити для кожного об'єкта з `test.csv`, чи висилати бригаду.

**Варіант** — остання цифра вашого номера за списком. Дані лежать у `variants/<варіант>/`.

## Вартості

| Подія | Вартість |
|---|---|
| виїзд бригади до об'єкта | `cost_visit` грн, незалежно від того, що знайшли |
| об'єкт, до якого не виїхали, відмовив | `cost_failure` грн |
| об'єкт, до якого виїхали | не відмовляє: бригада усуває дефект |

Бригад вистачає на будь-який список.

| Варіант | `cost_visit`, грн | `cost_failure`, грн |
|---|---|---|
| 0, 4, 7 | 1800 | 60000 |
| 1, 5, 8 | 2750 | 50000 |
| 2, 6 | 4080 | 48000 |
| 3, 9 | 5500 | 50000 |

## Дані

`registry.csv` — один рядок на об'єкт, 6000 об'єктів.

| Колонка | Тип | Min | Max | Опис |

`train.csv` — об'єкти `history`, для яких відомо, чи вони відмовили. `test.csv` — усі об'єкти `current`, ті самі колонки без `failed`. Ознаки пораховано з добових вимірювань за 8 тижнів: для `history` — з 5 січня по 1 березня 2026, для `current` — з 2 березня по 26 квітня. Межі в таблиці спільні для всіх варіантів.

Пропусків немає. Відмов у `train.csv` — від 5% до 9%.

## Пастки

Метрики на навчальних даних можуть обіцяти те, чого модель на нових об'єктах не дасть. У ваших даних є одна пастка з трьох. Перевірте кожну способом із колонки «Як перевірити» і покажіть числом, є вона чи ні. Знайдену обробіть так, як сказано в колонці «Що зробити».

| Код | Пастка | Як перевірити | Є, якщо | Що зробити |
|---|---|---|---|---|
| M-1 | Витік: колонка стає відомою лише після відмови й майже повторює мітку | AUC кожної числової колонки `train.csv` самої по собі проти `failed`; якщо AUC менше 0.5, взяти 1 − AUC | AUC більше 0.9 | прибрати колонку з ознак train і test |
| M-2 | Зміщена вибірка: результат відомий лише для частини об'єктів `history`, переважно підозрілих | кількість рядків `train.csv`, поділена на кількість об'єктів `history` у `registry.csv` | менше 0.9 | у коді нічого, рішення для test будується так само; частку відмов і ефект на валідації не переносити на весь парк |
| M-3 | Зсув у часі: у другому періоді температурний датчик показує інакше | (середнє `temp_rise_mean` у test − середнє в train) / стандартне відхилення в train, зі знаком | більше 0.5 | чотири колонки `temp_*` стандартизувати окремо в train і окремо в test |
